# 私人日记（AstrBot 插件）

一个只服务“主人”的私聊日记插件。它把主人在私聊里说的话和机器人的回复按天存下来，每晚让模型以机器人的第一人称写一篇日记存在本地；只有主人发 `/日记` 才能看到。它还会从聊天里整理一份关于机器人自己的“自我笔记”，在主人私聊时悄悄注入系统提示词，让机器人前后的性格、喜好和心情连得上。

插件只处理配置里填的那一个 QQ 号的私聊。群聊、其他人的私聊都不会被记录，也不会收到任何回复。

> 插件名 `astrbot_plugin_dafeiyu_diary` 是历史命名，功能与任何人设无关，可以配给任意 AstrBot 人设使用。

## 功能特性

- **只记录主人私聊**：监听私聊事件，只有会话标识等于“适配器 ID + `FriendMessage` + 主人 QQ”时才记录；其他人、群聊一律忽略。
- **成对记录聊天**：主人发的消息以 `owner` 记录；机器人回复后把回复文本以 `bot` 记录。代码会跳过两类回复：以 `✅` 开头的确认类回执，以及日记/笔记命令本身产生的输出（带内部跳过标记），避免把回执和日记正文当成聊天内容。
- **跳过指令消息**：主人发出的指令类消息（如 `/日记`、`/自我笔记`、`/reset`、`/new` 等）不会进入聊天记录，避免把命令当聊天内容喂给模型。
- **每晚自动写日记**：到了 `write_time`（默认北京时间 23:50），用当天完整记录写一篇第一人称日记，存成 `diary/YYYY-MM-DD.md`。如果这天在写点前已经有临时稿，这一步会重写它并定为终稿。
- **补写漏掉的日记**：AstrBot 重启后等 `catch_up_delay_seconds`（默认 120 秒），把“有聊天记录但还没写日记”的历史日期补写，并把跨过写点仍留着的临时稿定稿；夜间任务也会再次扫描。
- **当日按需生成**：写点（`write_time`，默认 23:50）之前，主人发 `/日记` 或「看看日记」查看今天，若已有聊天记录，会当场写一篇**临时稿**并缓存。定稿前再问，返回同一篇，不重复调用模型。到了写点，夜间任务用当天完整记录把临时稿**重写为定稿**；定稿之后再问，还是这一篇，不再改。已经过完的日期如果只留下临时稿（比如当晚没跑成），下次启动补写时会定稿。
- **日记查询**：`/日记` 看今天，`/日记 昨天`、`/日记 11-06`、`/日记 2025-12-31` 看指定日期，`/日记 列表` 列出最近写过日记的 10 天。
- **整理自我笔记**：写完某天的日记后，让模型把“机器人自己明确说过的喜好、看法、习惯、口头禅”整理成一份笔记；新旧冲突以最近一次为准，重复内容合并，上限 `max_self_notes`（默认 30）条。
- **查看与删除自我笔记**：`/自我笔记` 列出全部条目，`/自我笔记 删 3` 删除第 3 条。
- **私聊背景注入**：主人私聊触发 LLM 时，把自我笔记和最近 `inject_diary_days` 篇日记追加到系统提示词末尾，每篇最多 `inject_diary_chars` 字。同时写明：想看日记只能靠 `/日记` 拿原文，不要在聊天里念、改或另写一篇，没写的日期不能编，截断也不是“私藏”。
- **多模型顺序回退**：`provider_ids` 按顺序尝试，某个提供商不存在或调用报错就换下一个，全部失败则本次不写日记，并在日志里留警告。
- **原始记录自动清理**：`raw_retention_days` 天前的原始聊天记录会被删除，但**只删已经写成日记的那天**，没写成日记的记录不会丢。
- **不主动推送**：插件不会主动给主人发消息，日记只在 `/日记` 请求时返回。

## 适用场景 / 不适用场景

适合：

- 单主人、QQ 私聊为主的 AstrBot 实例，希望机器人对长期对话有连续性。
- 想要一份本地可读、可备份、可手动编辑的私聊日记文件。
- 想让人设里的偏好和口癖保持稳定，而不是每次对话都重新描述。

不适合：

- 多用户共享一个实例、需要给多个“主人”分别记日记的场景（本插件只认一个主人 QQ）。
- 群聊记录、公开分享日记、自动发到 QQ 空间的场景（插件没有这些功能）。
- 不想把私聊内容发给第三方模型提供商的场景（生成日记时聊天记录确实会发给模型）。
- 非 QQ 适配器（代码按 `FriendMessage` 的会话结构判断，其他平台未验证）。

## 工作原理

### 数据从哪来

1. AstrBot 收到一条私聊消息，`record_owner` 以 `priority=10` 先判断是不是主人私聊：
   - 是，且文本不匹配指令过滤正则 → 写入当天 `logs/YYYY-MM-DD.jsonl`，一行一条：`{"t": "20:15", "role": "owner", "text": "..."}`。
   - 不是主人私聊 → 直接返回，不记录。
2. 机器人回复发出后，`record_reply` 取回复文本，排除 `✅` 开头和日记输出，写入 `role: "bot"` 的记录。

### 什么时候处理

- **夜间任务**：启动后计算距 `write_time` 的秒数并等待，到点执行一次“补写 + 写今天 + 整理笔记 + 清理旧记录”，然后睡 61 秒再进入下一轮，保证一天只触发一次。
- **启动补写**：启动后等 `catch_up_delay_seconds` 秒，执行一次“只补今天之前的漏写日期 + 清理旧记录”。
- **LLM 请求时**：主人私聊触发 `on_llm_request`，读自我笔记和最近日记拼进系统提示词。

### 日记怎么生成

- 取当天记录，拼成 `[HH:MM] 他：...` / `[HH:MM] 我：...` 的文本，超过 `max_log_chars` 字只保留最后一部分。
- 系统提示词要求：第一人称、称呼主人为“他”、把当天主要互动按先后写清（大约 400～900 字，互动少就短）、只把有记录的互动当事实、不编造线下经历、虚拟日程/穿搭/待办不进入日记。
- 模型返回文本后存成 `diary/YYYY-MM-DD.md`。写点之前生成的当天日记记为临时稿（`diary_meta.json`）；同一天在定稿前再看，直接返回这篇临时稿。到写点或补写时，临时稿会用当时完整的聊天记录重写一次并改为定稿。定稿之后不再调用模型。

### 自我笔记

- 每写完一天的日记，若这天还没整理过笔记，就把“旧笔记 + 当天记录”交给模型整理。
- 只保留模型输出里以 `- ` 开头的条目（也接受 `*`、`•`、`·` 和编号列表，会统一成 `- `），去重、去掉“暂无”占位，最多 `max_self_notes` 条。
- 结果存 `self_notes.md`；整理过的日期记在 `notes_meta.json`（最多保留 60 天标记），避免同一天重复整理。
- 模型返回空或调用失败时不覆盖旧笔记。

### 注入怎么发生

只在 `inject_enabled` 为真且事件是主人私聊时：

- 有自我笔记 → 在系统提示词里追加 `【关于我自己】...`
- 有最近日记 → 追加 `【我最近的日记】日期：正文前 350 字...`
- 注入只改写本次请求的系统提示词，不发送任何额外消息，也不会出现在群里。

### 数据存在哪

全部在 AstrBot 的插件数据目录下（代码通过 `StarTools.get_data_dir("astrbot_plugin_dafeiyu_diary")` 获取，AstrBot 4.x 通常位于 `<AstrBot 数据目录>/plugin_data/astrbot_plugin_dafeiyu_diary/`，以实际运行环境为准）：

```
astrbot_plugin_dafeiyu_diary/
  logs/
    2026-11-08.jsonl      # 当天的原始聊天记录
  diary/
    2026-11-08.md         # 当天写好的日记
  self_notes.md           # 自我笔记（- 开头，一行一条）
  notes_meta.json         # 已整理过笔记的日期
  diary_meta.json         # 仍是临时稿的日期；定稿后从名单里去掉
```

日志行格式：

```json
{"t": "20:15", "role": "owner", "text": "今天有点累"}
{"t": "20:16", "role": "bot", "text": "那早点睡"}
```

## 安装

前置：已部署 AstrBot（4.16.0 及以上），已配置一个可用的 QQ 适配器（aiocqhttp），并已配置至少一个文本模型提供商。

### 方式一：AstrBot 插件市场

1. 打开 AstrBot 管理后台 → 插件市场。
2. 搜索插件名 `astrbot_plugin_dafeiyu_diary` 或显示名“私人日记”。
3. 点击安装，安装完成后到“插件管理”里确认已启用。
4. 打开插件配置，填写 `owner_qq`、`provider_ids` 等必填项。

### 方式二：后台上传 zip

1. 把本仓库根目录（含 `metadata.yaml` 的那一层）打包成 zip。
2. 后台 → 插件管理 → 上传/安装插件，选择这个 zip。
3. 安装完成后确认目录名是 `astrbot_plugin_dafeiyu_diary`，再填写配置。

> zip 里最好直接是插件文件；如果多包了一层同名文件夹，多数 AstrBot 版本也能识别，但以你实际后台的提示为准。

### 方式三：手动放到 data/plugins

1. 下载仓库代码（或 `git clone` 到本地）。
2. 把整个目录放到 AstrBot 的 `data/plugins/` 下，目录名保持 `astrbot_plugin_dafeiyu_diary`。
3. 重启 AstrBot，在插件管理页确认加载成功。
4. 在后台插件配置里填写配置并保存。

## 配置项详解

配置文件在 AstrBot 后台 → 插件管理 → 本插件 → 配置，字段与 `_conf_schema.json` 一一对应。

| 配置项 | 类型 | 默认值 | 作用 | 注意事项 |
| --- | --- | --- | --- | --- |
| `owner_qq` | string | `""` | 主人 QQ 号 | 只认这个号的私聊；留空则插件完全不记录、不响应。填纯数字。 |
| `adapter_id` | string | `""` | QQ 平台适配器实例 ID | 用来拼会话标识 `适配器ID:FriendMessage:QQ`。留空时从主人私聊事件的会话标识里自动推断。 |
| `provider_ids` | list | `[]` | 写日记/整理笔记用的模型提供商 ID，按顺序尝试 | 填 AstrBot 后台“服务提供商”里的 ID，例如 `deepseek/deepseek-chat`。留空或全部失败则不写日记。 |
| `write_time` | string | `"23:50"` | 每晚写日记的时间（北京时间 HH:MM） | 写“当天”的日记；错过会在下次启动后补写。 |
| `raw_retention_days` | int | `7` | 原始聊天记录保留天数 | 只删除已经写成日记的旧记录；没有日记的日志不删。日记本身永久保留。 |
| `max_log_chars` | int | `6000` | 单日交给模型的记录最大字数 | 超长时只保留最后一段，避免超出模型上下文。 |
| `catch_up_delay_seconds` | int | `120` | 启动后多久补写漏掉的日记 | 给模型服务留初始化时间；设太小可能启动瞬间调用失败。 |
| `inject_enabled` | bool | `true` | 主人私聊时是否注入自我笔记和最近日记 | 只影响系统提示词，不额外发消息。 |
| `inject_diary_days` | int | `2` | 注入最近几篇日记 | 设 0 表示只注入自我笔记。 |
| `inject_diary_chars` | int | `350` | 每篇日记最多注入多少字 | 超长截断并加省略号。 |
| `max_self_notes` | int | `30` | 自我笔记最多条数 | 超过后整理时合并或删掉最不重要的；可用 `/自我笔记` 手动删。 |

配置示例（写入 AstrBot 后台对应字段即可，不需要手改文件）：

```json
{
  "owner_qq": "123456789",
  "adapter_id": "",
  "provider_ids": ["deepseek/deepseek-chat"],
  "write_time": "23:50",
  "raw_retention_days": 7,
  "inject_enabled": true,
  "inject_diary_days": 2
}
```

## 使用方法

默认指令前缀是 `/`；如果你在 AstrBot 里改过指令前缀，请按改后的写。

### 命令

| 命令 | 作用 | 说明 |
| --- | --- | --- |
| `/日记` | 查看今天的日记 | 今天还没聊天记录会回复“今天还没跟我聊几句呢，没得写。”；有记录但没写过会当场生成。写点前生成的是临时稿，到点会按全天重写。 |
| `看看日记` | 和 `/日记` 一样，直接回原文 | 也认「看一下今天的日记」「念一下昨天的日记」「发给我 11-06 的日记」「看看日记列表」。句子里要有「日记」。不认「我看看今天的」这种没写出「日记」两个字的话，也不认闲聊（比如评价日记写得怎么样）。 |
| `/日记 昨天` | 查看昨天 | 也接受 `/日记 昨日`。 |
| `/日记 11-06` | 查看本年 11 月 6 日 | 年份省略时按今年算；也接受 `11-6` 这种不补零的写法。 |
| `/日记 2025-12-31` | 查看指定日期 | 支持 `YYYY-MM-DD` 和 `M-D` 两种格式。 |
| `/日记 列表` | 列出写过的日记 | 也接受 `/日记 目录`；按日期倒序最多 10 天。 |
| `/自我笔记` | 查看自我笔记 | 编号列出全部条目。 |
| `/自我笔记 删 3` | 删除第 3 条 | 编号范围不对时会提示。 |

### 自动行为

- 主人每发一条非指令私聊消息都会被记录；机器人的回复也会被记录。
- 每晚 `write_time` 自动写当天日记，并整理自我笔记。
- AstrBot 重启后自动补写过去漏掉的日记。
- 主人私聊触发其它对话时，自动注入自我笔记和最近日记。

### 权限边界

- 所有命令、记录、注入都只对 `owner_qq` 本人、且必须是私聊生效。
- 其他 QQ 私聊、任何群聊：不记录、不回复、不注入。
- 主人发这些命令时会终止事件继续传播（`event.stop_event()`），所以其它插件和默认对话不会再对这条命令作答。

## 数据与隐私

- **存储位置**：AstrBot 插件数据目录（见“工作原理”）。全部是本机文件，不传任何自建服务器。
- **会外发什么**：写日记和整理笔记时，插件会把当天聊天记录（最多 `max_log_chars` 字）发送给你在 `provider_ids` 里配置的模型提供商。这是唯一的网络外发路径。不想外发就不要配置 `provider_ids`（但也就写不出日记），或改用本地部署的模型服务。
- **谁能看到**：只有能接触这台机器插件数据目录的人；聊天里只有主人在私聊发 `/日记` 才会收到日记内容。
- **保留多久**：日记和自我笔记永久保留；原始聊天记录保留 `raw_retention_days` 天（默认 7 天），且只删已写日记的日期。
- **怎么清空**：
  - 清空某天聊天记录：停 AstrBot 后删除 `logs/对应日期.jsonl`。
  - 清空日记：删除 `diary/` 下的 `.md` 文件。
  - 清空自我笔记：`/自我笔记 删 编号` 逐条删，或直接删 `self_notes.md`。
  - 全部清空：卸载插件后删除整个插件数据目录。
- **备份**：备份整个插件数据目录即可，文件都是纯文本。

## 依赖与前置条件

- **AstrBot**：`>=4.16.0`（见 `metadata.yaml`）。
- **平台适配器**：aiocqhttp（QQ）。插件按 `<adapter_id>:FriendMessage:<owner_qq>` 判断主人私聊；其他适配器的会话结构不同，未验证。
- **模型提供商**：需要在 AstrBot 后台配置至少一个文本模型；把提供商 ID 填进 `provider_ids`。全部失败时不写日记。
- **Python 包**：没有额外第三方依赖，不需要 `pip install`（仓库不含 `requirements.txt`，仅用 AstrBot 自身依赖与标准库）。
- **权限**：AstrBot 进程需要对插件数据目录有写权限；`/日记` 写当前会话需要 AstrBot 正常运行。

## 常见问题 FAQ

**1. 装好后发 `/日记` 完全没反应？**

先确认 `owner_qq` 填了纯数字 QQ 号，且是在私聊里发；群聊和别人的私聊不会有任何回复。`owner_qq` 留空时插件直接不工作。

**2. 不知道 `adapter_id` 填什么？**

到 AstrBot 后台“平台适配器”页面看这个 QQ 适配器实例的 ID。留空也行：代码会从主人私聊事件里自动推断会话前缀。填错会表现为“发什么都不响应”。

**3. 日记一直是空的，日志里有 `[diary] provider ... failed`？**

`provider_ids` 里填的 ID 在 AstrBot 后台“服务提供商”里找不到，或该提供商调用出错。确认填的是提供商 ID（如 `deepseek/deepseek-chat`），不是显示名称；有多个就按顺序都填上做回退。

**4. 晚上 23:50 没写，重启后才补上？**

夜间任务依赖进程一直运行。如果那个时间点 AstrBot 在重启/停机，启动后等 `catch_up_delay_seconds` 秒会补写过去漏掉的日期；“今天”的那篇由夜间任务写，跨天后会被当作漏写日期补上。

**5. 服务器时区不是东八区，时间会乱吗？**

不会。代码内部固定按 UTC+8 计算“今天”和 `write_time`，与服务器系统时区无关。

**6. 能不能让原始聊天记录保留更久？**

调大 `raw_retention_days` 即可。注意插件只清理“已经写成日记”的旧日志，避免日记没写成记录先没了。

**7. 自我笔记写进了奇怪内容 / 越积越多？**

先用 `/自我笔记` 看看，用 `/自我笔记 删 编号` 删掉不对的条目；再调小 `max_self_notes`。提示词已要求不记主人的个人信息、不记一时情绪、不记角色扮演的日程和 AI/程序相关话题。

**8. 日记会不会被发到群里或主动推送给主人？**

不会。插件没有任何主动发送逻辑；日记只在主人私聊发 `/日记` 时返回。

**9. 换模型后旧日记要重写吗？**

定稿不会自动重写。写点前生成的当天临时稿，会在写点（或下次补写）用完整记录重写一次。想重写一篇定稿，删掉对应 `diary/YYYY-MM-DD.md`，再发 `/日记 日期`，或等补写任务处理（补写会处理还没有日记的日期，以及仍标着临时稿的日期）。

**10. 卸载插件后数据还在吗？**

在。插件卸载不会删插件数据目录，需要手动删除；重装后旧日记和笔记还能继续用。

## 兼容性

- **适配器**：只验证过 aiocqhttp 的 QQ 私聊。其他适配器（如 Telegram）会话标识结构不同，是否能匹配主人需要自行验证。
- **其他插件**：日记本身不调用别的插件。`SKIP_OWNER` 会跳过 `日记`、`自我笔记`、`reset`、`new`、`help`、`sid`、`qzone`、`写说说` 等常见指令词，避免把它们当聊天记录；如果你用的插件指令恰好以这些词开头，那些消息也不会进日记。
- **系统提示词注入**：注入内容追加在 `system_prompt` 末尾，和 AstrBot 自带人设、记忆类插件可以共存；如果同时装了其他“长期记忆”插件，可能出现内容重复。
- **AstrBot 版本**：依赖 `Star`、`StarTools`、`filter`、`ProviderRequest` 等 4.x 接口；更老版本未验证。

## 开发者说明

### 目录结构

```
astrbot_plugin_dafeiyu_diary/
  main.py            # 插件入口：事件监听、夜间循环、命令、模型调用
  diary_core.py      # 纯函数：时间、解析、存储、提示词拼接（不 import AstrBot）
  _conf_schema.json  # 后台可视化配置定义
  metadata.yaml      # 插件元信息
  README.md
  LICENSE
  .gitignore
  tests/
    test_core.py     # diary_core 的单元测试
    test_plugin.py   # 用打桩的 AstrBot 模块测试 main.py
```

### 跑测试

在插件目录下执行：

```powershell
py -m unittest discover -s tests -v
```

说明：

- `test_core.py` 只测试 `diary_core.py` 的纯逻辑（记录读写、截断、日期解析、清理策略、提示词拼接）。
- `test_plugin.py` 不 import 真实 AstrBot：它用 `sys.modules` 注入 `astrbot` 的桩模块，再用 `importlib` 加载 `main.py`，测试主人过滤、命令行为、模型回退、补写、注入等。
- Windows PowerShell 里测试输出走 stderr 时可能显示成红色，但只要结尾是 `OK` 就通过。

### 改代码注意点

- `diary_core.py` 保持不 import AstrBot，方便单测；AstrBot 相关逻辑只放 `main.py`。
- 数据路径统一走 `StarTools.get_data_dir(PLUGIN)`，不要写死本机路径。
- 时间统一用 `now_cst()` / `CST`（UTC+8），不要混用系统时区。
- 改命令名、前缀过滤正则时同步更新 README 和 `tests/test_plugin.py`。
- 不要在日志里打印聊天全文或任何密钥。
